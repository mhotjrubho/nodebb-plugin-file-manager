# NodeBB File Manager

תוסף לניהול קובצי NodeBB מתוך לוח הבקרה (ACP), בממשק עברי ורספונסיבי.

## גרסה
0.4.0 - שדרוג אבטחה וממשק ניהול.

## יכולות
- ניווט בתיקיות וקבצים תחת תיקיית ההתקנה של NodeBB.
- עריכת קובצי טקסט UTF-8 עד 2MB, עם שמירה אטומית וגיבוי לפני דריסה.
- יצירה, שינוי שם, העתקה והעברה של קבצים ותיקיות.
- העברת פריטים שנמחקו לסל מחזור פרטי, עם אפשרות שחזור או מחיקה לצמיתות.
- העלאת קבצים בודדים, מספר קבצים או תיקייה שלמה תוך שמירה על מבנה התיקיות.
- חילוץ ZIP עם בדיקות נתיבים, קישורים סמליים, סוגי קבצים, מגבלות גודל ומניעת דריסה.
- חיפוש שמות קבצים ותיקיות עם מגבלת עומק ומספר פריטים לסריקה.
- רשימת גיבויים ושחזור גרסה קודמת.
- ממשק ACP בעברית, כולל תצוגה מותאמת לנייד.

## הגבלות אבטחה
- ממשק הניהול ופעולות השרת מוגבלים למנהלי NodeBB.
- בדיקת הרשאת מנהל מתבצעת לפני קבלת קובצי multipart בהעלאה.
- שורש העבודה מוגבל לנתיב base_dir של NodeBB.
- נתיבים מוחלטים, מעבר באמצעות נקודתיים כפולות (..), קישורים סמליים ונתיבים לתיקיית הגיבויים הפנימית חסומים.
- תיקיית .file-manager-backups מוסתרת מרשימת הקבצים ומוגנת מפעולות רגילות של מנהל הקבצים.
- מחיקה רגילה מעבירה פריטים לסל מחזור פרטי במקום למחוק אותם מיד.
- שחזור גיבוי של קובץ קיים יוצר תחילה גיבוי של הגרסה הנוכחית.
- אין מסוף פקודות ואין API להרצת פקודות מערכת.
- עריכת קובץ מוגבלת ל-2MB.
- העלאה מוגבלת ל-100MB לקובץ ול-500MB לבקשה מצד התוסף. בפועל, מגבלת NodeBB maximumFileSize יכולה להיות נמוכה יותר והיא גוברת על מגבלת התוסף.
- NodeBB 4.16.7 מגביל multipart ל-20 קבצים לבקשה; הממשק מחלק העלאה למנות של עד 20.
- ZIP מוגבל ל-100MB, עד 5,000 פריטים, עד 100MB לקובץ ועד 500MB תוכן מחולץ.
- תיקיית הגיבויים נשמרת בהרשאות 0700, וקובצי המטא-נתונים בהרשאות 0600.
- שגיאות מערכת פנימיות נרשמות בלוג השרת ומוחזרות לממשק כהודעה כללית, כדי לא לחשוף נתיבי מערכת ופרטי מימוש.

## תאימות
- NodeBB 4.16.x (נבדק מול קוד המקור של v4.16.7)
- Node.js 20 ומעלה
- תלות: yauzl

## התקנה ועדכון
יש לבצע גיבוי מלא של NodeBB לפני התקנה או עדכון. מומלץ לבצע בדיקה בסביבת staging תחילה. לאחר עדכון התוסף יש לבנות מחדש את NodeBB לפי נוהל ההתקנה הרגיל.

## הערת אבטחה חשובה
התוסף מבצע פעולות קבצים בתהליך NodeBB, ולעיתים התהליך פועל בהרשאות מערכת רחבות. בדיקות נתיבים וקישורים סמליים מפחיתות סיכון, אך אינן מבטלות לחלוטין מרוץ זמן (TOCTOU) כאשר משתמש מקומי אחר משנה את מערכת הקבצים במקביל. יש להגביל גישה לשרת ולתהליך NodeBB, להשתמש בחשבונות מנהל מהימנים, לשמור גיבויים מחוץ לשרת, ולבדוק בסביבת staging לפני שימוש בקבצים קריטיים.

בדיקות CI בודקות תחביר JavaScript, מבנה manifest, התקנת תלות והתאמה סטטית בין הממשק לתבנית. הן אינן תחליף לבדיקת אבטחה ולהרצת תרחישי קצה על שרת.
