# NodeBB File Manager

מנהל קבצים עבור NodeBB 4.16.x, עם ממשק עברי בהשראת Windows 11 File Explorer, ניווט תיקיות, רשימת קבצים, תצוגה מקדימה, עורך CodeMirror והרשאות נפרדות למשתמשים.

## גרסה 0.8.0

- תיקון חלוקת העמודות ל־RTL אמיתי: אזור הניווט מימין, רשימת הקבצים במרכז, ותצוגה מקדימה או עורך משמאל. נתיבים וקוד נשארים LTR.
- מעבר לממשק רחב יותר עם סרגל פעולות, סרגל כתובת, רשימת פרטים, שורות גדולות יותר וטיפוגרפיה קריאה יותר.
- בקשת מפתח אישי בכניסה למנהל הקבצים, לפני הצגת רשימת הקבצים.
- אימות אישי נפתח בצד השרת למשך 15 דקות. כל קריאות הקבצים ופעולות השינוי מחייבות הרשאת session תקפה.
- פקיעת האימות דורשת הזנה חוזרת של המפתח. פעולות קריאה, שינוי, העלאה וניהול הרשאות משתמשות באותו מנגנון.
- איפוס מפתח אישי מבטל גם הרשאות session שנפתחו קודם לכן, באמצעות זיהוי גרסת credential המבוססת על salt ו־hash.
- טעינת CodeMirror משתמשת בממשק RequireJS הגלובלי להגדרת נתיב נכסי התוסף, וב־AMD loader המקומי לטעינת המודולים.
- לא נעשו שינויים בקובצי הליבה של NodeBB.

## התקנה ואתחול ראשוני

**חשוב:** הרשאות File Manager נשמרות ב־NodeBB meta settings, ולכן מחיקת התוסף או התקנתו מחדש אינה בהכרח מוחקת את רשימת המנהלים והמשתמשים המורשים.

קובץ מפתח האתחול נמצא כברירת מחדל ב:
`~/.nodebb-file-manager-bootstrap`

הקובץ נקרא מתיקיית הבית של משתמש מערכת ההפעלה שמריץ את NodeBB, וחייב להיות קובץ רגיל בהרשאות `0600`. לדוגמה, אם NodeBB פועל כ־root:

```bash
umask 077
openssl rand -hex 32 > /root/.nodebb-file-manager-bootstrap
chmod 600 /root/.nodebb-file-manager-bootstrap
stat -c '%a %U:%G %n' /root/.nodebb-file-manager-bootstrap
```

תוצאת `stat` צריכה להציג הרשאה `600`. אין לשתף את מפתח האתחול בצ'אט או עם משתמשים אחרים.

### מנהל שמבצע אתחול ראשון

כאשר לחשבון אין עדיין הרשאת מנהל קבצים:
1. מנהל NodeBB נכנס לעמוד מנהל הקבצים.
2. מזין את מפתח האתחול ששמור בקובץ השרת.
3. מזין את סיסמת חשבון NodeBB שלו. התוסף משתמש במנגנון הרשמי `middleware.requirePasswordAuth` של NodeBB כדי לאמת אותה.
4. החשבון נרשם כמנהל קבצים מורשה.
5. לאחר מכן נדרש להגדיר מפתח אישי למנהל הקבצים.

### מנהל שכבר אושר בעבר

אם החשבון כבר מופיע ברשימת מנהלי הקבצים שנשמרה ב־NodeBB, שלב מפתח האתחול לא יופיע שוב. זה מכוון: ההרשאה נשמרה במסד הנתונים גם אם התוסף הוסר והותקן מחדש.

עם זאת, בגרסה 0.8.0 הכניסה לממשק עצמו עדיין מחייבת את המפתח האישי. משתמש שכבר הוגדר לו מפתח יתבקש להזין אותו בכל כניסה. משתמש מורשה שעדיין לא הגדיר מפתח יופנה להגדרתו לפני הצגת הקבצים.

מפתח האתחול נשאר מפתח התאוששות: מנהל NodeBB שמחזיק בו יכול להוסיף את עצמו מחדש כמנהל קבצים במקרה שכל ההרשאות אבדו. יש להגביל את הגישה אליו.

## אימות ומפתחות אישיים

- לכל משתמש מורשה יש מפתח אישי נפרד מסיסמת NodeBB.
- המפתח חייב להכיל לפחות 12 תווים.
- בעת הגדרת מפתח או החלפתו, נדרש גם אימות סיסמת NodeBB באמצעות מנגנון האימות הרשמי של NodeBB.
- סיסמת מנהל הקבצים אינה נשמרת גלויה: נשמרים salt אקראי ו־hash מסוג scrypt, וההשוואה מתבצעת בזמן קבוע.
- לאחר אימות מוצלח, השרת פותח הרשאת session למשך 15 דקות.
- קריאת רשימות תיקיות, קריאת קובץ, תצוגה מקדימה, חיפוש, גיבויים, העלאה ופעולות שינוי דורשות session מאומת.
- עם פקיעת הזמן, המשתמש מתבקש להזין שוב את המפתח האישי.
- חמש טעויות רצופות גורמות לנעילת ניסיונות מאותה כתובת IP עבור המשתמש למשך 15 דקות. מונה הניסיונות נשמר בזיכרון התהליך ומתאפס בהפעלה מחדש.
- מנהל קבצים יכול לאפס מפתח אישי של משתמש, אך אינו יכול לראות את הסיסמה המקורית.
- איפוס המפתח משנה את salt וה־hash ולכן מבטל sessions קיימים של המשתמש.
- פעולות ניהול רגישות, כגון שינוי רשימת מורשים ואיפוס מפתח, דורשות גם אימות מחודש של סיסמת NodeBB.

## רמות הרשאה

- **צפייה:** קריאה בלבד תחת `public`.
- **עריכה:** גישה לקריאה ולשינוי קבצים ותיקיות בתוך תיקיית NodeBB.
- **מנהל קבצים:** גישה מלאה, ניהול משתמשים והרשאות ואיפוס מפתחות.

הרשאת עריכה וניהול מלאה מאפשרת לשנות קובצי קוד של NodeBB ותוספים. יש להעניק אותה רק לאנשים מהימנים ברמה טכנית גבוהה.

## ממשק ויכולות

- ממשק Explorer רחב, עם סרגל פעולות עליון, סרגל נתיב וחיפוש.
- בממשק העברי, אזור הניווט מוצג מימין, רשימת הקבצים במרכז והתצוגה המקדימה משמאל. כאשר נפתח עורך, הוא תופס את אזור התצוגה המקדימה.
- שמות קבצים, נתיבים ותוכן קוד נשארים LTR, בעוד כותרות והוראות בעברית מוצגות RTL.
- תצוגת פרטים ותצוגת סמלים, חיפוש, ניווט מהיר ומידע על הקובץ שנבחר.
- תצוגה מקדימה לתמונות PNG, JPEG, GIF, WebP, AVIF, BMP, SVG ו־ICO עד 8MB.
- תצוגה מקדימה לקובצי טקסט וקוד נתמכים.
- עורך CodeMirror 5.65.20 מקומי, ללא CDN חיצוני, עם מספרי שורות, הדגשת תחביר, קיפול, חיפוש, התאמת סוגריים, סגירת תגיות, מסך מלא ושמירה ב־Ctrl+S.
- אם CodeMirror אינו נטען, עורך טקסט חלופי מאפשר להמשיך לעבוד. במקרה כזה אין הדגשת תחביר או תכונות CodeMirror.
- העלאת קבצים ותיקיות תוך שמירת מבנה התיקיות, התקדמות וביטול העלאה פעילה.
- יצירה, שינוי שם, העתקה, העברה, מחיקה לסל מחזור, שחזור, מחיקה לצמיתות, גיבויים וחילוץ ZIP.

## מגבלות

- שורש העבודה מוגבל לתיקיית ההתקנה של NodeBB. אין גישה לנתיבים מחוץ לה.
- עריכת קובץ מוגבלת ל־2MB, תצוגה מקדימה של תמונה מוגבלת ל־8MB.
- העלאה מוגבלת ל־100MB לקובץ ול־500MB לבקשה מצד התוסף. מגבלות NodeBB עשויות להיות נמוכות יותר.
- ZIP מוגבל ל־100MB, עד 5,000 פריטים ועד 500MB תוכן מחולץ.
- ביטול העלאה מפסיק בקשות שטרם הושלמו; קבצים שכבר נשמרו בשרת אינם נמחקים אוטומטית.
- אין ניהול הרשאות מערכת Unix מסוג `chmod` או `chown`, אין הורדת תיקייה כ־ZIP ואין חיבור FTP/SFTP חיצוני.
- אין מסוף פקודות ואין הרצת shell מתוך ממשק הדפדפן.

## הפעלת פרויקט Node.js נפרד

מנהל הקבצים אינו מריץ `npm install`, `npm start` או פקודות מערכת. פרויקט Node.js נפרד יש להעלות לתיקייה נפרדת מחוץ לשורש NodeBB באמצעות SSH/SFTP או מנגנון הפריסה של השרת, להתקין בו תלויות ולהפעיל באמצעות PM2 או שירות מערכת. כדי להציג אותו בעמוד NodeBB, יש לפרסם אותו דרך reverse proxy עם HTTPS ולהטמיע כתובת iframe בווידג'ט HTML.

## תאימות ובדיקות

- NodeBB 4.16.x, נבדק מול קוד המקור של v4.16.7.
- Node.js 20 ומעלה.
- תלויות: `yauzl`, `codemirror 5.65.20`.

בדיקות CI כוללות התקנת תלויות, בדיקת תחביר JavaScript, קיום נכסי CodeMirror, בדיקות הרשאות, מפתח אתחול, מפתחות משתמשים, אימות session והתאמה בין הקוד לתבנית. בדיקות CI אינן תחליף לבדיקת דפדפן מול שרת NodeBB חי.

## אבטחה

התוסף מבצע פעולות קבצים מתוך תהליך NodeBB, שלעיתים פועל בהרשאות מערכת רחבות. בדיקות נתיבים וקישורים סמליים מפחיתות סיכון אך אינן מבטלות לחלוטין מרוץ זמן (TOCTOU). יש להגביל גישה לשרת ולתהליך NodeBB, להעניק הרשאות שינוי רק למשתמשים מהימנים ולשמור גיבויים מחוץ לשרת.
